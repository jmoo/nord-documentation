######################################################

Nord Electro 5 program file (extension ne5p)
Piano section 0x3a to 0x41, Sample section 0x46 to 0x4d.

######################################################

Piano category
Offset in file 0x3a (b7-b5)
0 = Grand
1 = Upright
2 = Electric Piano 1
3 = Electric Piano 2
4 = Clavinet
5 = Harpsichord

Unused
Offset in file 0x3a (b4-b3)
always 0 on every file seen

Piano model
Offset in file 0x3a (b2-b0) and 0x3b (b7-b6)
0 = first model in the category, 1 = second . . .

Note: category and model together are the piano's position in the instrument's
library. The library is organised one bank per category, so category is the bank
and model is the slot within it, both counted from 0, so the piano in bank 3
slot 2 stores 2/1. Verified against pianos read back over USB. These are
positions, so they move if the library is reorganised - the piano ID below is
the stable reference.

Unused
Offset in file 0x3b (b5-b1)
always 0 on every file seen

Clavinet model
Offset in file 0x3b (b0) and 0x3c (b7)
0 to 3
only set when the piano category is Clavinet, 0 on every other file seen

Piano acoustics
Offset in file 0x3c (b6-b5)
0 = OFF
1 = String Resonance
2 = Long Release
3 = String Resonance and Long Release
Note: the names come from the settings the test files were made with. String
Resonance was confirmed by ear; Long Release made no audible difference on the
piano it was tried with.

Piano touch
Offset in file 0x3c (b4-b3)
0 = OFF
1 = Touch 1
2 = Touch 2
3 = Touch 3

Note: touch remaps the velocity played rather than the level. All three settings
lift soft notes by about 10 velocity steps; the higher the setting, the more the
middle of the range is lifted too.

Piano mono
Offset in file 0x3c (b2)
0 = OFF
1 = ON

Piano ID
Offset in file 0x3c (b1-b0) and 0x3d to 0x3f and 0x40 (b7-b2)
32-bit identifier of the piano (.npno) this program depends on
0 = no piano referenced

Note: this is the identity of the piano, independent of where it sits in the
library. The instrument reports the same value when asked for a program's
dependencies over USB, which is how a program can be matched to the piano it
needs.

Unused
Offset in file 0x40 (b1-b0) and 0x41 to 0x45
always 0 on every file seen

######################################################

Sample attack
Offset in file 0x46 (b7-b1)
0 - 127, 0 = 0.5 ms to 127 = 45 s, the curve in between is not known

Sample decay/release
Offset in file 0x46 (b0) and 0x47 (b7-b2)
0 - 127, 0 = 3 ms decay . . . 64 = sustain . . . 127 = longest release

Note: one knob covers both. Below 64 it sets a decay, above 64 a release, and 64
(sustain) is the knob's centre detent.

Sample number
Offset in file 0x47 (b1-b0) and 0x48 (b7-b2)
position of the sample in the Samp Lib, counted from 0
(0 = the sample shown as 1 on the panel)

Note: this is a panel position only. It does not match the sample's slot in the
instrument's sample library, and it is reused - the same number appears against
different samples, and the same sample appears under different numbers. The
instrument does not use it to pick the sample: a program whose number and ID
disagree plays the sample the ID names. Use the sample ID below to identify a
sample.

Sample ID
Offset in file 0x48 (b1-b0) and 0x49 to 0x4b and 0x4c (b7-b2)
32-bit identifier of the sample (.nsmp) this program depends on
0 = no sample referenced

Sample dynamics
Offset in file 0x4c (b1-b0)
0 to 3

Sample filter
Offset in file 0x4d (b7)
0 = OFF
1 = ON

Unused
Offset in file 0x4d (b6-b0)
always 0 on every file seen
